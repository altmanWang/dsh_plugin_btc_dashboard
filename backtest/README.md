# BTCUSDT 永续合约回测框架

单标的历史 K 线回测：**OKX `BTC-USDT-SWAP`**，可指定时间范围与 K 线周期，默认 **1 倍杠杆**、
**maker 0.0200% / taker 0.0500%** 手续费，输出控制台摘要 + JSON + 自包含 HTML + 交易 CSV。

- **纯 ESM、零第三方依赖**（Node ≥ 20，本机 v24），不需要 `npm install`
- **不需要 API key**：只读 OKX 公开行情接口（`/market/history-candles`），全部是公开数据
- **历史 K 线本地磁盘缓存**：同一段区间第二次回测不再联网；`--offline` 保证一个请求都不发
- **策略插件化**：内置 `buy-hold`（基线）与 `sma-cross`（双均线）；新策略 = 往
  `backtest/strategies/` 丢一个 `.mjs`，不用动引擎
- **可复现**：报告里的时间都是 UTC 毫秒时间戳，展示统一 `YYYY-MM-DD HH:mm UTC+8`；
  `--data` 能把某次回测的 K 线固定成文件，之后离线重跑
- **CLI 与看板是同一份实现**：1.6.0 起 DSH 看板插件里内置了「回测」面板
  （工具条按钮 → 选策略/区间/资金/杠杆/费率 → 面板内看资金曲线/指标/交易 → 打开完整报告），
  Host 半按需动态 import 的就是这里的 `lib/*.mjs`；集成契约见 `INTEGRATION-SPEC.md`

> 定位：**研究/教学用的近似回测**。撮合、保证金、爆仓都是近似模型（见[局限](#局限明确不做的事)），
> 不是清结算级仿真，也不构成投资建议。

## 快速开始

在**仓库根目录**执行（路径都相对仓库根，clone 到任何位置都能跑）：

```powershell
# 1) 真数据：最近 30 天、1h K 线、双均线策略（首次会联网抓取并缓存，之后读缓存）
node backtest/run.mjs --strategy sma-cross --start now-30d --bar 1h

# 2) 基线对照：同一段区间跑 buy-hold，两份报告对比
node backtest/run.mjs --strategy buy-hold --start now-30d --bar 1h

# 3) 指定区间与资金/杠杆/费率（费率支持 0.0002 与 0.0200% 两种写法）
node backtest/run.mjs --strategy sma-cross --start 2025-01-01 --end 2025-02-01 `
  --capital 10000 --leverage 2 --maker 0.02% --taker 0.05% `
  --param fast=10 --param slow=30
```

第一次跑会看到取数进度（抓了几页、命中缓存没有），然后打印：
性能摘要、交易统计、费用、Buy&Hold 基准对比，最后是三个报告文件的路径。

### 完全离线（`--data`）：把某段 K 线固定成文件

```powershell
# 先把区间跑一次，缓存落在 backtest/data/BTC-USDT-SWAP/1h.json；
# 缓存文件里就带 bars 字段，可以直接当 --data 的输入（同样会按 --start/--end 过滤）。
node backtest/run.mjs --strategy buy-hold `
  --data backtest/data/BTC-USDT-SWAP/1h.json `
  --start 2025-01-01 --end 2025-02-01 `
  --out-dir backtest/reports

# 只想用缓存、不允许任何联网：缓存没覆盖区间会报错退出（退出码 1）
node backtest/run.mjs --strategy buy-hold --offline --start 2025-01-01 --end 2025-02-01
```

任何符合下面任一形状的 JSON 都能作 `--data`（`readBarFile` 支持）：

```jsonc
{ "bars": [[1704067200000, 42000, 42100, 41900, 42050, 123.4], ...] } // 数组行
{ "bars": [{ "t": 1704067200000, "o": 42000, "h": 42100, "l": 41900, "c": 42050, "v": 123.4 }, ...] }
[ [1704067200000, 42000, 42100, 41900, 42050, 123.4], ... ]          // 裸数组
```

> **`--data` 也按 `--start/--end` 过滤（`start <= t < end`）**。否则用户改了时间范围、结果却不变，
> 这是最难查的一种「假回测」。默认范围是 `now-30d → now`，所以喂 2024 年的 fixture 时必须
> 显式给 `--start/--end`，否则会报「时间范围内没有 K 线」并返回 1。
>
> `--data` 模式下不联网、不读写缓存目录。`--data-dir` 只影响联网模式的缓存位置。

## 内置策略与推荐预设

> ⚠️ **v1.7 起 CLI/看板默认计入资金费率（funding）**：下面的策略表格是 v1.6 的「不含 funding」口径，
> 便于和旧结果对比；含 funding 的调整见「资金费率」一节（breakout-hold 近 3 年 36.4% → 29.5%、
> 2020 起 62.2% → 54.1%）。想复现旧口径加 `--no-funding`。

| 策略 | 类型 | 推荐周期 | 默认参数 | 说明 |
|---|---|---|---|---|
| `buy-hold` | 基线 | 任意 | — | 首根满仓做多持有到期末；用来给其它策略做对照 |
| `sma-cross` | 示例 | 1h/4h | `fast=20 slow=60 allowShort=false` | 双均线交叉，最简单的趋势策略；示例用 |
| **`multi-tf-dual`** | 多周期双向 | **4h** | `entryWindow=36 exitWindow=120 trendWindow=200 dailyWindow=225 shortWindow=24 shortExitWindow=48 shortAtrStop=0 regimeSlopeDays=10 volTarget=0 allowShort=true` | **多空主策略（v1.8 新增）**：4h 内部聚合日线定 regime，日线熊市才允许做空；多头慢出场、空头快回补。2020 起总收益 **+4448%**、回撤 28.5%（不含 funding） |
| `adaptive-dual` | 1D 双向 | 1D | `entryWindow=5 longExitWindow=12 shortExitWindow=6 trendWindow=50 longWindow=200 bearMode='slope' reversalMode='immediate' allowShort=true atrStop=5 volTarget=0.5` | 1D 多空备选（v1.8 新增）：MA200 熊市闸门 + 非对称出场 + 波动率目标仓位 + ATR 止损。2020 起 **+3136%**；验证段最强 |
| **`breakout-hold`** | 突破 + 滞回 | **4h** | `entryWindow=36 ma=240 enterBuffer=0.008 exitBuffer=0.008 weight=1` | **只做多主策略**：突破 36 根新高才买、跌破 MA240 下轨才卖。入场要强势确认、出场容忍回调，回调后二次上涨不会踏空 |
| `ma-hysteresis` | 均线滞回 | 4h | `window=240 enterBuffer=0.008 exitBuffer=0.008 weight=1` | 站上均线上轨就持有、跌破下轨才卖；交易更多、2022 更差，但长历史略高 |
| `donchian-trend` | 突破趋势 | 4h | `entryWindow=36 exitWindow=36 trendWindow=120 atrStop=0 allowShort=false slopeFilter=false weight=1` | 唐奇安突破型；近 3 年最强，但长历史回撤大（59.9%） |
| `ema-regime` | 趋势跟随 | 4h | `fast=10 slow=100 trendWindow=0 atrStop=0 allowShort=false weight=1` | EMA 交叉 + ATR 止损；备选，交易更频繁、回撤更大 |

### `ma-hysteresis`：为什么它更贴合"回调 + 二次上涨"（新推荐主策略）

唐奇安要求"突破 36 根新高"才买，所以**回调后必须再创新高才能重新上车**；这个策略换了规则：

- 收盘 > `MA240 × 1.008` → 持有（不要求创新高）；
- 收盘 < `MA240 × 0.992` → 平仓（回调不深就拿着，过滤均线附近的来回摩擦）；
- 平仓后收盘重新 > `MA240 × 1.008` → **立刻再入场**，不用等新高。

```powershell
# 4h、默认参数、最近 3 年
node backtest/run.mjs --strategy ma-hysteresis --bar 4h --start now-1095d --end now
```

| 指标（4h、1x、默认费率） | 2019-12 起（6.8 年） | 2020 起 | 近 3 年 |
|---|---|---|---|
| 年化收益 | **66.7%** | **62.6%** | 33.4% |
| 最大回撤 | **32.4%** | **32.4%** | 31.4% |
| Sharpe / Calmar | 1.47 / **2.06** | 1.40 / **1.93** | 1.08 / 1.06 |
| 交易次数 / 胜率 | 70 / 30.0% | 70 / 28.6% | 34 / 26.5% |
| 持仓时间占比 | 53% | 53% | 54% |
| 对比：唐奇安默认档 | 46.5% / 59.9% DD / 0.78 | 44.5% / 59.9% / 0.74 | 45.5% / 18.4% / 2.48 |

分年度（2020 起）：2020 +308%、2021 **+134%**、2022 **-24%**、2023 +116%、2024 +93%、2025 -1.4%、2026（到 10 月）+12%。
> 2021 那种"牛市但反复震荡"的年份，唐奇安默认档只有 +11%（因为要等新高），这个策略能拿到 +134% ——
> 这正是"回调后二次上涨"被抓住的地方。
>
> ⚠️ 同样的诚实提醒：窗口/滞回带参数是在这段历史上选的（240 根 ±0.8% 附近是一个参数平台，
> 不是单点尖峰，但仍有选择偏差）；2022 单边熊市照样亏 24%；2025 基本走平；
> **不含资金费率**（v1.6 口径；含 funding 的调整见「资金费率」一节）；近 3 年窗口它反而跑不过唐奇安默认档（33.4% vs 45.5%，但回撤 31% vs 18%）。
> 结论：**长历史 + 想抓回调/二次上涨 → 用 `ma-hysteresis`；只想吃近 3 年这波、接受 60% 级别的历史回撤 → 用唐奇安默认档**。

### `breakout-hold`：「突破入场 + 均线滞回出场」（当前推荐主策略）

`ma-hysteresis` 是"只要是上涨趋势就一直拿"，而 `donchian-trend` 是"突破买、破位卖"。
把两者的优点拆开重组后更好：**入场用突破**（只在真正走强时买，避免在均线附近瞎进），
**出场用均线滞回**（回调不深就拿着，二次上涨不会因为"没创新高"而踏空）。

```powershell
# 4h、默认参数、2020 起（或 now-1095d 看近 3 年）
node backtest/run.mjs --strategy breakout-hold --bar 4h --start 2020-01-01 --end now
```

| 指标（4h、1x、默认费率） | 2019-12 起（6.8 年） | 2020 起 | 近 3 年 |
|---|---|---|---|
| 年化收益 | **65.1%** | **62.2%** | **36.4%** |
| 最大回撤 | 34.5% | 34.5% | 27.8% |
| Sharpe / Calmar | 1.48 / **1.89** | 1.43 / 1.80 | 1.17 / **1.31** |
| 交易次数 / 胜率 | 50 / 38% | 50 / 36% | 25 / 32% |
| 持仓时间占比 | 50% | 50% | 51% |
| 累计手续费（USDT） | 7,367 | 6,411 | 488 |

分年度（2020 起）：2020 +223%、2021 **+112%**、2022 **-19%**、2023 +110%、2024 +91%、2025 +8%、2026（到 10 月）+15%。
> 和 `ma-hysteresis` 比：长历史几乎打平（65.1% vs 66.7%），但**近 3 年更好（36.4% vs 33.9%）**、
> **2022 少亏 4 个百分点（-19% vs -24%）**、交易更少（50 vs 70）、胜率更高（38% vs 30%）。

**"双策略按年份切换"被 walk-forward 否掉了**：2021–2026 每年用之前数据按 Calmar 在
「唐奇安默认 / 唐奇安稳健 / ma-hysteresis / breakout-hold」里挑一个策略、当年使用，
累计 **+289.8%**；而固定使用 `breakout-hold` 同期累计 **+324.8%**。
**策略切换本身就是在拟合历史**，所以最终交付的是这个固定结构的融合策略，而不是切换器。

> ⚠️ 老规矩：参数在 24–48 根突破窗口 × 0.8–1.5% 带子范围内是一片平台（Calmar 1.7–1.9），不是单点尖峰，
> 但仍是历史内选择；**2022 年仍亏 19%**；以上是不含资金费率口径（含 funding：近 3 年 36.4% → 29.5%、
> 2020 起 62.2% → 54.1%）；近 3 年也跑不过唐奇安默认档的 45.5%（但回撤 27.8% vs 18.4%）。
> 选哪个取决于你想要"长历史稳"还是"最近这波猛"。

### `multi-tf-dual`：多周期双向趋势（4h，当前收益最高的策略）

**本仓库第一个默认同时做多和做空的策略**（v1.8 新增）。做法是把「4h 执行」和「日线级趋势确认」拼在一起：

- 4h 数据内部每 6 根聚合成一根 UTC 日线（当天最后一根 4h 即 UTC 20:00 那根收盘后才更新日线因子，天然无未来函数）；
- **日线熊市闸门（硬规则）**：只有「日线收盘 < 日线 MA225 且 MA 多日（10 日）下行」时才允许做空 —— 2024 那种震荡上行里空头 -5.3 万 USDT 的亏损被直接消掉；
- **非对称出场**：多头用 120 根（20 天）通道 + 4h 趋势 MA(200) 拐头才走（慢出场、吃满趋势）；空头用 48 根（8 天）通道回补 + MA 拐头/日线转牛就平（快出场、避免被反弹或逼空打爆）；
- 多头只在日线非熊时开仓（不在长期熊市里抄底）；4h 突破入场（多头 36 根新高、空头 24 根新低）。

```powershell
# 2020 起（主口径：不含资金费率，方便与 v1.6 旧结果对比）
node backtest/run.mjs --strategy multi-tf-dual --bar 4h --start 2020-01-01 --end now --no-funding
# 含资金费率（默认口径）
node backtest/run.mjs --strategy multi-tf-dual --bar 4h --start 2020-01-01 --end now
```

实测（4h、1x、默认费率、2020-01-01 → 2026-10-17，1D 最新缓存到 2026-10-17）：

| 指标 | **multi-tf-dual** | breakout-hold（原只做多主策略） | donchian 稳健档（参照） |
|---|---|---|---|
| 总收益（不含 funding） | **+4448.33%** | +2585.52% | +1520.47% |
| 年化收益 | **75.29%** | 62.22% | 50.61% |
| 最大回撤 | **28.51%** | 34.50% | 38.36% |
| Sharpe / Calmar | 1.62 / **2.64** | 1.43 / 1.80 | 1.32 / 1.32 |
| 交易次数 / 胜率 | 68 / 45.6% | 50 / 36% | 87 / 42.5% |
| 含 funding（0.01%/8h 估算） | **+3568.60%** | +1792.05% | +1112.01% |
| 验证段 2024-10→now（冷启动） | **+66.89%**（年化 28.50%、回撤 22.70%） | +29.03% | +51.02% |
| 验证段 2024-10→now（连续运行切片） | **+91.47%**（年化 37.45%） | +71.49% | +63.51% |

分年度（连续口径，UTC+8）：2020 **+272.7%**、2021 **+159.2%**、2022 **+27.3%**（同年 Buy&Hold -64%）、2023 +66.0%、2024 +66.8%、2025 **-1.1%**、2026（到 10 月）+35.0%。

验证（`backtest/tools/verify-dual.mjs`，离线可复现）：**因果探针**（数据截断 60%/85% 重跑）截断前 8,937/12,660 个权益点差异 0、成交逐笔一致；**walk-forward**（训练段 2020-01→2024-10 的 60 组网格选参）3 种切分验证段 +80.96% / +259.33% / +66.89%，60/60 组验证段全正；**参数邻域** 10 个参数共 47 个取值里 45 个仍 >2585.52%（平台不是孤点）；funding 0.005% / 0.01% / 0.02% 三档总收益 +3969.51% / +3568.60% / +2872.18%，即使 0.02% 也高于只做多主策略。

> ⚠️ **必须知道的局限**：
> 1. 默认参数是**只用训练段 2020-01→2024-10-02 做 60 组网格选出来的**（验证段不参与选择），但**整个结构是在看过全历史后设计的**，仍有选择偏差，不等于真实样本外。
> 2. 收益高度集中在 2020-2022（约 73% 的权益倍数来自这三年）；2025 震荡年约 -1.1%，2023/2024 的慢牛里跑输只做多的 breakout-hold —— 双向策略的代价是震荡年接近打平。
> 3. 2022 年单看「独立启动」回测是 -11.4%，连续运行口径才 +27.3%（空头段收益依赖前面的权益基数），披露时必须标口径。
> 4. 4h 数据内部聚合日线依赖「4h 按 UTC 整点对齐、每天 6 根」；换到其它周期上日线因子会失真（策略会写 log 警告）。
> 5. 含 funding 的大头是估算值（OKX 历史只有近 3 个月）；成交是近似撮合、无盘口深度/容量建模。

### `adaptive-dual`：1D 双向趋势（备选）

1D 周期的双向版本（v1.8 新增），结构同样是「空头只在熊市 + 非对称出场」，另外启用波动率目标仓位与 ATR 跟踪止损：

- 空头闸门：收盘 < MA200 且 MA200 下行；多头出场用 12 日最低、空头出场用 6 日最高（非对称）；
- 波动率目标 0.5（高波动自动减仓）、ATR 5 倍跟踪止损。


### 优化实验结论（2026-10，4h、1x、默认费率）

所以这轮的"优化"落地成两件事：① `donchian-trend` 新增 `slopeFilter` 参数（默认关，保持交付行为不变）；
② README/面板里把 `slopeFilter=true + exitWindow=60` 作为**稳健档**推荐。下一步最值得做的是
资金费率已在 v1.7 计入（见「资金费率」一节）；下一步最值得做的是**限价单入场降成本**（把每轮往返的 taker 费率换成 maker），
以及把 walk-forward 做成正式工具。

## 超短线（1h）实验：可以跑，但不建议当主策略

结论先说：**1h/更短周期在 1x + 默认 taker 费率下跑不过 4h**。测过的策略族与结果（4h、1x、含 funding）：

| 策略 | 2020 起年化 / 回撤 / Calmar | 近 3 年年化 / 回撤 / Calmar | 交易数 |
|---|---|---|---|
| **4h `breakout-hold`（当前主策略）** | **54.1% / 35.3% / 1.53** | **29.5% / 30.3% / 0.97** | 50 / 25 |
| 1h 短唐奇安 `24/36/400`（带 400 根趋势过滤） | 34.0% / 38.5% / 0.88 | 14.8% / 38.1% / 0.39 | 279 / 132 |
| 1h 短唐奇安 `24/36/0`（无趋势过滤） | 22.5% / 69.6% / 0.32 | 24.3% / 24.3% | 408 笔 |

实测过的超短线候选（都在 1h 上，扣默认手续费、含 funding）：

- **短唐奇安突破**（entry 12–48 根 / exit 6–36 根 / 趋势过滤 0–400）：最好的是 `24/36/400`；
  无趋势过滤版 2022 年 **-49.5%**（熊市里反复做多被打爆），带过滤版 2022 -13.8% 但 2025 -33.2%。
- **EMA 交叉 5/20、10/60**：年化 -3% ~ +1%，交易 310–823 笔，被手续费吃光。
- **布林带均值回归**（20/2、30/2.5，中轨/上轨止盈）：市价版 3 年 -2% ~ +0.3%；
  换**限价 maker 进出**（往返 0.04%）后仍然是 -4% ~ +1%——名义上是"胜率 66%"，但单笔太薄。
- **RSI 均值回归**（14/30/55）：3 年 +2.2%，交易 175 笔，最好的结果也就是"不亏"。

为什么超短线难赚钱：

1. **手续费是固定百分比**：1h 交易 130–400 笔/3 年，taker 往返 0.1%，3 年累计手续费约占初始资金
   20%–30%（有复利时更直观：`24/36/400` 2020 起交了 14,673 USDT）；频率越高，成本占比越大。
2. **震荡年反复止损**：1h 级别噪音多，2022/2025 这种年份会被来回打；4h 的慢信号天然少踩几次。
3. **资金费率暴露时间更长**：1h 策略持仓占比 45–54%，funding 成本与 4h 接近，但收益更薄。

如果仍想试超短线（研究/改进用），最小可用预设是：

```powershell

node backtest/run.mjs --strategy donchian-trend --bar 1h --start 2020-01-01 --end now \
  --param entryWindow=24 --param exitWindow=36 --param trendWindow=400
```

> 想真正做超短线，下一步需要的是**降低执行成本**（限价 maker 进出、VIP/返佣费率表），
> 而不是更复杂的指标；现有引擎已支持限价单（`ctx.limit`，maker 费率），但把策略改成纯 maker 执行还没做。

### 杠杆测试：10x 以上必爆（引擎实测）

用引擎的杠杆/爆仓逻辑跑同一批策略（含 funding），结论毫不意外：**杠杆只放大方差，不改变正负期望**，
而且爆仓线是硬约束。4h `breakout-hold`（2020 起）：

| 杠杆 | 年化 | 最大回撤 | 爆仓次数 | 结果 |
|---|---|---|---|---|
| 1x | 54.1% | 35.3% | 0 | 189,205 USDT |
| 2x | 96.4% | 50.4% | 0 | 984,169 |
| 3x | 126.5% | 64.9% | 0 | 2,598,893 |
| 5x | 148.0% | 82.6% | 0 | 4,813,133 |
| **10x** | **-100%** | 100% | **3** | 归零（首爆 2020-02-20） |
| 20x | -100% | 100% | 6 | 归零（首爆 2020-02-15） |
| 50x | -100% | 100% | 12 | 归零（首爆 2020-02-13） |
| 100x | -99.1% | 100% | **43** | 归零（首爆 2020-02-12） |

- 5m 短唐奇安（1 年）：1x 已 -35.7%；2x -60.5%；3x -76.8%；10x -99.8%；20x 归零（0 次爆仓是因为复利亏损先耗光保证金）；
  50x 起出现爆仓（11 次，首爆 2025-11-11）；100x 爆仓 36 次、归零。
- **100x 即便零手续费、零资金费率**：4h 仍爆仓 63 次、5m 爆仓 70 次，最终权益 0 ——
  死因是爆仓线（100x 多头约 -0.5%、空头约 +0.5%）而不是成本。
- 100x 的算数：taker 往返 0.1% × 100 倍名义 = **每次买卖约 10% 初始权益**；
  funding 0.01%/8h × 100 倍名义 ≈ **3%/天**；再叠加 ±0.5% 的爆仓线，任何策略都活不过几次波动。
- 实盘含义：**不要用 100x**。2–3x 是"收益/回撤"还不算离谱的极限（2x 的 Calmar 1.91 甚至略好于 1x，
  但回撤 50%）；5x 以上回撤 80%+，10x 起确定性归零。杠杆不能替代策略 edge 和成本优化。

### 「1% 资金 + 100x」≠「1% 仓位」：引擎可以跑，但结果是严格更差

可以用 `--param weight=0.01 --leverage 100` 表达"用 1% 权益做保证金、开 100x"：
**名义仓位 = 1% × 100 × 权益 = 1 倍权益**（和 1x 满仓同规模），但爆仓线按 100x 算仍约 **±0.5%**。
4h `breakout-hold`（2020 起，含 funding）实测：

| 配置 | 年化 | 最大回撤 | Calmar | 交易数 | 爆仓次数 |
|---|---|---|---|---|---|
| 1x × weight=1（基准：100% 权益名义） | **54.1%** | 35.3% | 1.53 | 50 | 0 |
| **100x × weight=0.01（1% 保证金 + 100x）** | **33.4%** | 38.4% | 0.87 | 177 | **167**（首爆 2020-02-12） |
| 1x × weight=0.01（真·1% 仓位） | 0.6% | 1.1% | 0.57 | 50 | 0 |

- 名义规模一样，但 100x 版的 **±0.5% 爆仓线** 在 6.8 年里触发 **167 次**强平；每次强平 ~0.5% 权益损失
  再重新进场，年化从 54.1% 掉到 33.4%，Calmar 从 1.53 掉到 0.87。**手续费/资金费按名义（=权益）计，
  与 1x 相同**，并不会因为"杠杆高"而按 100 倍扣。
- 5m 同理：1x 已经 -35.7%，100x × weight=0.01 是 -35.2%（几乎一样，但多了 185 次爆仓和更高手续费）。
- 想要"只用 1% 资金" → 就是 **1x 下 weight=0.01**（收益小、回撤 1.1%，但不会爆仓）。
- 想要"每笔最多亏 1% 权益" → 这是**风险定仓**，不是 1% 保证金：应按止损距离算仓位
  （`weight ≈ 1% / 止损距离`，例如止损 2% → 仓位 50%；止损 5% → 仓位 20%），再配合策略止损使用。
  当前内置策略的 `weight` 是固定仓位，风险定仓需要策略自己按 ATR/止损算 weight（引擎支持，每个策略都可改）。

## 参数扫描（`backtest/tools/sweep.mjs`，研究用）

手改参数一次跑一回太慢，而且**很容易全样本过拟合**。这个工具一次跑完一组参数笛卡尔积，
并支持训练/验证切分：用前段数据排名、看后段的表现（后段不参与选择）。

```powershell
# 近 3 年 4h，扫唐奇安参数；前 70% 训练、后 30% 验证
node backtest/tools/sweep.mjs --strategy donchian-trend --bar 4h \
  --start now-1095d --end now --walk 0.7 --top 15 \
  --grid "entryWindow=24,36,48,60;exitWindow=24,36,48,60;trendWindow=80,100,120,200;allowShort=false" \
  --out backtest/reports/sweep-donchian.json
```

- `--walk 0.7`：前 70% 训练、后 30% 验证；不传就是全样本排名（**只能用来找候选，不能当结论**）。
- `--sort`：排名指标（默认 `annualizedReturnPct`；`maxDrawdownPct` 会按越小越好排）。
- `--out`：把每组的完整指标（含每段收益/回撤/夏普/费用）写成 JSON，方便二次分析。
- 输出表里的「验证」列是**不参与选择的**，用它判断参数是「真的稳」还是「拟合出来的尖峰」；
  邻域里一片都好（而不是只有一个点好）才值得继续看。
- 参数扫描本身不解决过拟合：换时间段、换周期、看邻域稳定性，都是必须做的检查。

## 手续费、杠杆与保证金口径

### 费率

- 默认 **maker 0.0200% = 0.0002**、**taker 0.0500% = 0.0005**（来自 `lib/config.mjs`，
  CLI 默认值也印在 `--help` 里）。`--maker 0.02%` 与 `--maker 0.0002` 等价。
- 手续费**从现金扣**，报告里分 maker / taker 汇总，并给出占初始资金比例。
- 哪些单子收哪种费：
  - **taker**：市价单（`ctx.market` / `ctx.target` 的成交）、爆仓强平、期末平仓
  - **maker**：限价单成交（`ctx.limit`，成交价 = 挂单价）
- 两个内置策略都只用 `ctx.target`（市价单），所以默认费率下**一轮往返 ≈ 2 × 0.05% = 0.1% 名义价值**
  （1 倍杠杆时约等于权益的 0.1%，实际随仓位与价格变化）。想测 maker 成本就自己用
  `ctx.limit` 挂单，报告会自动把它记成 maker 费用。
- 市价滑点默认 **0 bps**（`config.slippageBps`，v1 CLI 未暴露 —— 给一个假精度不如不给）。

### 杠杆与保证金

- 默认 1 倍。`ctx.target({ side, weight })` 的**目标名义价值** = `权益 × 杠杆 × weight`
  （weight ∈ [0, 1]），引擎在下一根开盘价上换算成数量。
- 权益：`equity(price) = cash + qty × (price − avgEntry)`（持仓中）；平仓时已实现盈亏进 `cash`。
- 已用保证金：`|qty| × price / 杠杆`；可用 = 权益 − 已用保证金。
  下单前检查「成交后保证金需求 ≤ 权益」，不满足就**拒绝委托**（报告里计入「被拒委托」）。
- 爆仓价（近似，忽略手续费与资金费）：
  - 多头：`avgEntry × (1 − 1/杠杆 + 维持保证金率)`
  - 空头：`avgEntry × (1 + 1/杠杆 − 维持保证金率)`
  - 当根 K 线的最低价/最高价穿过爆仓价时全平（taker 手续费），记入爆仓次数与交易明细。
  - **1 倍杠杆下多头爆仓价 ≈ 0、空头 ≈ 2 倍入场价**——这是公式的正确结果，不是 bug；
    高杠杆下才会在正常波动里看到爆仓。
- `closeAtEnd: true`（默认）：最后一根收盘后按收盘价强制平掉剩余持仓（taker），
  保证最终权益 = 已实现现金。

### 资金费率（funding，v1.7 起默认计入）

永续合约每 **8 小时**结算一次资金费率：费率为正时多头付、空头收；为负反之。v1.7 之前的版本完全没算这一项，
v1.7 起 CLI 和看板面板**默认计入**，口径与限制：

- 结算发生在每根 K 线的 `[bar.t, bar.t + barMs)` 区间内；金额 = `持仓数量 × 当根收盘价 × 费率`
  （当根收盘价是对结算时刻标记价的近似，引擎没有逐笔标记价）。
- 费率来源：**OKX 公开历史接口，只保留最近约 3 个月**；超出部分按 `--funding-rate`
  指定的固定费率估算（默认 **0.0100% / 8h**）。报告和控制台会标注「估算 N 次」，不会把估算伪装成历史。
- 关掉：`--no-funding`（结果与 v1.6 一致）；估算费率可改：`--funding-rate 0.005%`。
- 资金费率缓存：`<data-dir>/<instId>/funding.json`（和 K 线缓存并列，自动抓取/合并/原子写）。
- 对结果的影响（breakout-hold，4h、1x、默认费率）：

| 窗口 | 不含 funding 年化 | 含 funding 年化 | 净付出（USDT） | 估算次数 |
|---|---|---|---|---|
| 2020-01 起（6.8 年） | 62.2% | **54.1%** | 34,131（复利口径） | 7,158 |
| 近 3 年 | 36.4% | **29.5%** | 2,818 | 2,996 |

**估算费率敏感性**（breakout-hold、近 3 年，其余条件相同）：

| 估算费率（/8h） | 年化收益 | 最大回撤 | Calmar | 资金费率净支出 |
|---|---|---|---|---|
| `--no-funding` | 36.4% | 27.8% | 1.31 | 0 |
| 0.005% | 32.7% | 28.9% | 1.13 | 1,584 |
| **0.010%（默认）** | **29.5%** | 30.3% | 0.97 | 2,818 |
| 0.020% | 23.4% | 33.1% | 0.71 | 5,025 |

> 参考：OKX 最近 3 个月实际 funding 均值约 **0.0049%/8h**（中位数 0.0048%，90% 的结算为正费率，
> 年化约 5.3%）。所以默认 0.01%/8h 相对最近三个月的实际水平是**偏保守**的估计；
> 但 2021 那种牛市里 funding 长期贴着 0.01% 基线也很常见，长区间到底用多少只能做敏感性分析。
> 既然 OKX 历史只有 3 个月，长区间里**大头是估算值**：拿结论前请至少跑 0.005% / 0.01% / 0.02% 三档。

## 数据：缓存、联网与 `--offline`

- 缓存路径：`<data-dir>/<instId>/<bar>.json`，例如 `backtest/data/BTC-USDT-SWAP/1h.json`。
  结构 `{ version, instId, bar, updatedAt, earliestKnown, segments, bars }`，`segments` 记录已覆盖的时间区间，
  相邻/重叠会合并；`earliestKnown` 记住 OKX 历史深度下界（往回翻到空页时记下），之后更早的区间
  不再重复翻空页。写入是「先写 `.tmp` 再 rename」的原子写，跑到一半中断不会留下半个文件。
  缓存文件本身是 `{ bars: [[t,o,h,l,c,v], ...] }` 形状，可以直接当 `--data` 的输入。
- **只缓存已收盘 K 线**（`t + bar 时长 <= now`，且接口标了 `confirm=1`），正在走的那根永远不参与回测。
  请求的时间范围也会按这个规则夹紧。已收盘边界用 `floor(now / barMs) * barMs`（同根 K 线内重复运行
  不会因为边界漂移误报缺口）；**不假设交易所按 UTC 对齐**——实测 `1D` 是按 UTC+8 零点对齐的。
- **历史深度（实测）**：`1m / 1h / 4h` 最早到 **2019-12-16 UTC**，`1D` 最早到 **2019-11-28（UTC+8）**，
  更早的区间接口返回空页；数据层把最早可用时间记进缓存的 `earliestKnown`，之后不再重复翻空页给 warning。
- 按**缺口**抓取：缓存已覆盖的段直接跳过；一次回测跨了很多页时会打印抓取进度。
  早期数据 OKX 拿不到时（比如很早之前的 1H）会把实际能取到的最早一根记成下界并给 warning，
  不会每次运行都重试同一段。
- **联网必须先查缓存**；`--offline` 时**一个网络请求都不发**：缓存没覆盖住区间就
  `ok:false` → CLI 打中文错误、退出码 1，而不是偷偷联网。
- 网络部分失败但已有一部分数据时：继续跑，但把缺口写进 warning（结果仅供参考）。
- 传输层复用看板插件的代理隧道：本机 DNS 会把 `www.okx.com` 解析到黑洞地址，直连超时，
  所以默认走 `http://127.0.0.1:7897`。代理地址优先级：
  `DSH_BTC_PROXY` / `OKX_PROXY` 环境变量 > 工作区 `.env` 同名键 > 默认本地代理；
  代理失败会自动回退直连并记住上次成功的通道。**任何情况下都不需要 API key**。
- 回测结束后 CLI 会在 `finally` 里关闭传输通道（否则 keep-alive 隧道会让进程不退出）。

## 输出报告

默认写到 `backtest/reports/`，文件名：

```
<outDir>/<instId>-<bar>-<strategy>-<起始YYYYMMDD>-<结束YYYYMMDD>.<json|html|csv>
例：backtest/reports/BTC-USDT-SWAP-1h-sma-cross-20250101-20250201.json
```

**控制台摘要**（`formatConsole`，等宽中文对齐、无颜色，重定向到文件也能读）包含：
配置摘要（标的/周期/时间范围/杠杆/手续费/初始资金）、绩效（总收益、年化、最大回撤、Sharpe、
Sortino、Calmar、波动率）、交易统计（次数/胜率/盈亏比/最大连亏）、费用（maker/taker/合计）、
Buy&Hold 基准对比、爆仓次数、被拒委托数。数值格式：金额 `1,234.56`、百分比 `12.34%`、
比率 `2.31`、无值 `—`。

**JSON 报告**：`{ generatedAt, framework, config, strategy, result, metrics }`。
`result` 里带**全量** `equityCurve` / `fills` / `trades`（可复现、可二次分析），
`config` 里是本次实际生效的费率/杠杆/区间。适合喂给 python/pandas 或做参数对比脚本。

**HTML 报告**：自包含单文件（内联 CSS + 内联 SVG），不引任何外部资源，**双击打开、断网也能看**。
包含标题、KPI 卡片、**价格 K 线图**（蜡烛 + 持仓底纹 + 开仓/平仓标记，可悬停看明细）、
资金曲线（含 Buy&Hold 基准）、回撤曲线、交易表（最多 500 行并注明截断）、配置表、局限说明。
没有 JS 也能看。

> K 线图会按桶聚合到 ≤480 根（1m×30 天 4 万根全画进 SVG 会有几 MB），并在图上方注明
> 「共 N 根 / 每 M 根聚合为 1 根」；交易标记只画最近 160 笔（完整明细在交易表/CSV）。

**CSV**：交易明细，表头英文（`seq,side,qty,entry_t,entry_price,exit_t,exit_price,pnl,pnl_pct,fees,bars,exit_reason`），

## 策略接口与 `ctx` API

策略是一个**纯对象**：`{ name, params, onStart?, onBar, onEnd? }`，用 `defineStrategy` 包一层校验。
策略只通过 `ctx` 下单，**不自己记账、不碰文件、不发网络请求**——账、手续费、保证金全由引擎算。

```js
// backtest/strategies/xxx.mjs
import { defineStrategy } from '../lib/strategy.mjs'

export default defineStrategy({
  name: 'xxx',                        // 报告里显示的名字；建议和文件名一致
  params: { fast: 20, slow: 60 },     // 默认参数；--param 按这里的类型转换覆盖
  onBar(ctx, bar, index) {            // 每根 K 线**收盘后**调用，产出的委托下一根才可能成交
    const { fast } = ctx.params       // 合并后的参数只从这里读
    // ...
  },
})
```

### `ctx` API 简表（完整定义见 `SPEC.md` §6.7）

| 成员 | 说明 |
|---|---|
| `ctx.index` / `ctx.time` / `ctx.bar` | 当前 K 线下标（0-based）/ 开盘时间戳 / 只读 K 线副本 |
| `ctx.params` | **合并后的策略参数只读快照**（`--param` 的覆盖值在这里；不要用 `this` 或模块变量） |
| `ctx.config` | 配置快照（instId/bar/leverage/makerFeeRate/takerFeeRate/initialCapital） |
| `ctx.equity` / `ctx.cash` | 当前收盘价上的权益 / 现金 |
| `ctx.position` | `{ side:'long'\|'short'\|'flat', qty, entryPrice, notional, unrealizedPnl }`，`qty` 有符号（正多负空） |
| `ctx.window(n)` | 最近 n 根 Bar（含当前），**返回副本、绝不包含未来** |
| `ctx.closes(n)` | 最近 n 个收盘价（含当前），同样不可能看到未来 |
| `ctx.log(msg)` | 写一条日志进报告（上限 5000 条，超出丢最早的） |
| `ctx.target({ side, weight, reason? })` | 目标仓位：`side:'long'\|'short'\|'flat'`，`weight∈[0,1]`，按下一根开盘价换算数量；`flat` 等价 weight=0 |
| `ctx.market({ side:'buy'\|'sell', qty?, notional?, reason? })` | 市价单；`notional` 在提交时按当前收盘价折算成数量 |
| `ctx.limit({ side, price, qty?, notional?, reduceOnly?, reason? })` | 限价单，返回 id；成交价 = 挂单价（maker 费率） |
| `ctx.cancel(id)` / `ctx.cancelAll()` | 撤单 |

几个必须记住的时序/语义：

1. **`onBar` 里下的单下一根才可能成交**：第 i 根收盘决策 → 第 i+1 根开盘价成交（市价单）。
   所以「看到信号的价格」和「成交价」天然差一根，这是回测的保守近似。
2. `window` / `closes` 只能看到 `0..i`，返回的是副本；策略改它不影响引擎。
3. 方向翻转（多→空 / 空→多）由引擎拆成**先平后反**两笔，各自的成交/费用都会进报告。
4. `onStart` 里下的单排到第 1 根 K 线；`onEnd` 里**不允许下单**（会抛错）。
5. 「只在信号变化时下单」：拿 `ctx.position.side` 和目标方向比，一致就别再下单；
   每根都 `ctx.target` 虽然不会重复成交（引擎算的是差值），但会白白制造噪音和拒单风险。

### 如何新增一个策略

1. 在 `backtest/strategies/` 新建 `my-first.mjs`（**文件名即 `--strategy` 用的名字**）：

   ```js
   import { defineStrategy } from '../lib/strategy.mjs'

   /** 最小示例：快线在慢线上方做多，下方空仓（只做多）。 */
   export default defineStrategy({
     name: 'my-first',
     params: { fast: 5, slow: 20 },
     onBar(ctx) {
       const { fast, slow } = ctx.params
       const closes = ctx.closes(slow)
       if (closes.length < slow) return // 预热期
       const average = (period) => {
         let sum = 0
         for (let i = closes.length - period; i < closes.length; i += 1) sum += closes[i]
         return sum / period
       }
       const desired = average(fast) > average(slow) ? 'long' : 'flat'
       if (ctx.position.side === desired) return
       if (desired === 'flat') ctx.target({ side: 'flat', weight: 0, reason: '均线下穿' })
       else ctx.target({ side: 'long', weight: 1, reason: '均线上穿' })
     },
   })
   ```

2. 直接跑（会自动出现在 `--list` 里）：

   ```powershell
   node backtest/run.mjs --list
   node backtest/run.mjs --strategy my-first --start now-30d --param fast=10
   ```

3. 也可以把策略放在别处，用路径加载：`--strategy ./my-strategy.mjs`。
4. 需要跨 K 线的状态（比如「连续 N 根」）就在策略文件里用闭包变量，并在 `onStart` 里重置；
   **不要**写模块级可变状态当参数（同一进程里跑多次回测会串）。
5. `--param` 的类型按默认值转换：默认是数字就转数字、布尔就只收 `true/false`、其余转字符串；
   **参数名拼错会直接报错**，不会静默忽略。

内置策略：

| 策略 | 参数 | 信号 |
|---|---|---|
| `buy-hold` | 无 | 第一根 onBar（index=0）用 `ctx.target({side:'long', weight:1})` 满仓做多，第 2 根开盘价成交并持有到期末（期末平仓） |
| `sma-cross` | `fast=20`, `slow=60`, `allowShort=false` | SMA 快慢均线：快线在慢线上方做多；下方 `allowShort=false` 时空仓、`true` 时做空。只在目标方向变化时下单 |

> `buy-hold` 与报告里的 **Buy&Hold 基准**不是一回事：前者走引擎的真实撮合（下一根开盘成交、
> 交 taker 费、可用杠杆、可能爆仓），后者是「首根收盘买入、末根收盘卖出」的现货口径
> （不收费、不加杠杆）。数值接近但不等，这是正常的。

## 局限（明确不做的事）

- **资金费率（funding）已计入（v1.7+）**：历史来自 OKX（只保留最近约 3 个月），更早区间按固定费率
  估算并在报告里标注次数 —— 长区间结果里资金费率大头是估算值，不是精确历史；用 `--no-funding`
  可退回不含资金费率的口径。
- **无盘口深度、无部分成交、无逐笔撮合**：限价单只有「整单成交 / 整单不成交」两种结果；
  大资金回测会低估冲击成本。
- **撮合是近似**：市价单按下一根开盘价 + 固定滑点（默认 0）成交；限价单按当根高低价判定
  （`tradeThrough` 默认：买价严格低于挂单价才算成交）；爆仓用当根极值与近似爆仓价。
- **爆仓价近似**：忽略手续费与资金费，且假设能在爆仓价全额成交（极端行情会滑点）。
- **只支持单标的、单方向净持仓**：无多标的组合、无多仓位、无对冲模式（OKX `posSide` 语义不同）、
  无「一键反向」的开平仓差异。
- **无手续费阶梯/VIP/返佣/BNB 抵扣**：手续费率是固定值。
- **不做自动寻优/组合优化**：`tools/sweep.mjs` 只是网格扫描 + 训练/验证切分，不做遗传算法、
  不做多标的组合、不做手续费/滑点敏感性分析（这些要自己写脚本）。
- **参数默认值是「历史内选出来的」**：内置策略的默认参数是在 2019-2026 这段历史上扫出来的，
  存在选择偏差；回测好看 ≠ 未来赚钱。README 里给了训练/验证拆分和更长窗口的结果供参考。
- **数据来自 OKX 公开历史接口**：早期数据可能取不到或中间有缺口，CLI 会打 warning；
  极端行情下的 K 线本身也可能与逐笔成交不一致。
- **金额用 JS number**：目标是口径正确，不是清结算级精度（不是 decimal 库）。
- **权益可以为负**（1 倍空头遇到超过 100% 的上涨），指标按实数计算，不夹到 0。
- **仅供研究**，不构成任何投资建议。

## 设计取舍（为什么长这样）

- **时间：内部 UTC 毫秒，展示 UTC+8**。交易所 K 线按 UTC 对齐，但用户按北京时间说日期；
  所以输入/展示都走 UTC+8，内部一律毫秒时间戳，避免哪一层偷偷用了本机时区。
- **区间左闭右开 `[start, end)`**：和数组切片、K 线编号的习惯一致；`end` 超过 now 会夹紧，
  因为没走完的 K 线不能当历史数据。
- **`--data` 也过滤时间范围**：用户换了范围结果却不变 = 假回测，宁可报错也不静默拿范围外数据凑数。
- **参数从 `ctx.params` 读**：`resolveParams` 只产出新的参数对象，闭包里的默认值不会变；
  如果靠 `this` 绑定或模块变量，`--param` 很容易「看起来生效、实际没生效」。
- **fetcher 在 `finally` 里 `close()`**：底层是 keep-alive 的代理隧道，不关进程不退出。
- **内置策略只做市价单**：成交时机确定、口径简单；限价单的成交判定（`tradeThrough`/`touch`）
  留给想研究 maker 成本的策略。
- **JSON 报告带全量成交/资金曲线**：报告是给人看的，但复盘和二次分析需要原始数据。
- **`--json` 只打一行**：方便脚本取最后一非空行 `JSON.parse`，不用在混合输出里配对括号。
- **错误不打印 stack**：CLI 用户要的是「哪里错了」；要调试就改代码，读调用栈不如直接看中文信息。
- **零第三方依赖**：这个仓库要能在没装任何 npm 包的机器上直接跑；回测的正确性也不依赖库。
