# dsh-btc-dashboard

DSH 插件：**OKX BTC 合约价格看板**。侧边栏一个按钮，点开是一个全屏面板：

- **最新价格**：OKX `BTC-USDT-SWAP` 的 last / 24h 涨跌 / 买卖价 / 24h 高低 / 24h 量（5 秒级刷新）
- **多周期 K 线**：`1m` `3m` `15m` `1h` `4h` `1D`，点标签切换（数字键 `1`–`6` 也行）
- **默认均线**：EMA20 与 EMA480（图例可点击显隐），**周期可在面板上改**，拖动/缩放时在整条序列上动态重算
- **周期切换**：面板顶部标签，选择会被记住（下次打开还是这个周期）
- **时间轴操作**：按住拖动平移、滚轮缩放（以光标为锚点）、双击复位、按住价格轴/时间轴拖动也能缩放（专业图表的老习惯）
- **最新价线与收盘倒计时**：跟随最新时在最后一根收盘价上画一条虚线 + 轴上价格标签，图区右上角常驻「收 mm:ss」倒计时；未收盘那根 K 线用半透明 + 描边标出来
- **时间刻度对齐整点**：刻度落在 1m/5m/15m/整小时/整天的边界上（不是把窗口等分），并带纵向网格线
- **悬浮两档**：指针压在 K 线实体/影线上才弹 OHLC / 量 / 均线数据框（横线吸附到收盘价）；只在画布空白处时，十字光标跟着鼠标走，价格轴上标出**鼠标位置对应的价格**
- **画线**：直线 + 斐波那契（默认 0 / 0.5 / 1 / 1.5 / 2，比例可改）+ **尺子**，按合约+周期分开保存；画完可以**点选、拖端点、整体拖动、隐藏、单条删除**，端点可**吸附到最近的 OHLC**
- **键盘**：`←/→` 平移 1 根、`Ctrl+←/→` 平移 20 根、`Ctrl+↑/↓` 或 `+/-` 缩放、`Alt+R` / `Home` 回最新、`End` 去最早、`1`–`6` 换周期、`Alt+H` 一键开关两条均线、`Delete` 删除选中的画线、`Esc` 退出画线/取消选中/关面板
- **无障碍**：面板是 `role="dialog" aria-modal="true"`，打开时焦点进面板、Tab 圈在面板内、关闭后焦点还原；canvas 带 `role="img"` 与描述当前视图的 `aria-label`；「数据陈旧」这类离散状态才挂 `aria-live`（价格更新不播报）
- **陈旧数据标记**：连续刷新失败超过 2.5 个轮询周期时，价格转为中性色并出现「数据 mm:ss 未更新」角标
- **画线**：直线 + 斐波那契（默认 0 / 0.5 / 1 / 1.5 / 2，比例可改），按合约+周期分开保存；画完可以**点选、拖端点、整体拖动、隐藏、单条删除**
- **生产 / 模拟环境切换**：面板顶部「模拟 / 生产」分段按钮，选择同样被记住

图表是原生 canvas 画的（蜡烛 + 影线 + 成交量 + 双均线 + 最新价线 + 十字光标浮层），不依赖任何图表库。

## 安装状态

已经通过 `plugin_manager` 的 `install_bundle` 装进当前 profile，`package.json` 里是一条链接依赖：

```
@local/dsh-btc-dashboard  link:D:/codes/dsh/btc_dashboard/plugin/dsh-btc-dashboard
```

所以**改这个目录里的代码就是改线上插件**（客户端半由宿主按原样读取文件字节发给浏览器，改完刷新页面即可；Host 半是已加载的 ESM 模块，代码改动需要重启宿主才生效）。

- 卸载：`plugin_manager` → `remove_bundle`，target `@local/dsh-btc-dashboard`
- 临时停用：`set_bundle` / `set_plugin`，enabled=false

## 两个环境的语义（重要，别被「密钥」误导）

| | 生产（prod） | 模拟（demo） |
|---|---|---|
| 读取的密钥 | `PROD_OKX_API_KEY/SECRET` | `DEBUG_OKX_API_KEY/SECRET` |
| 请求头 | 无 | `x-simulated-trading: 1` |
| 行情价格 | 实盘 | 与实盘一致（同一市场数据） |

**看板只用 OKX 公开行情接口（`/market/ticker`、`/market/candles`、`/market/history-candles`），不需要签名**，所以：

1. 密钥不是取价的前提 —— 面板照常工作，即使 `.env` 里一把钥匙都没有（页脚会提示）；
2. 密钥唯一的作用是「确认这一环境配了哪把钥匙」，面板只展示**掩码指纹**（如 `abcd12…9xyz`），secret 只用来判断「配没配」，永远不进浏览器；
3. **本插件不发任何私有请求**（不读账户余额、不读持仓），因此不需要 `passphrase`，也不需要签名 —— 相关代码已在 1.3.2 移除。

## 这台机器上的一个坑：必须走本地代理

本机 DNS 把 `www.okx.com` 解析成 `169.254.0.2`（链路本地黑洞地址），直连必然超时。
所以插件默认走本地代理 `http://127.0.0.1:7897`：先 `CONNECT` 建隧道，再在隧道里握 TLS，**并复用同一条 keep-alive 隧道**。

实测对比（12 次连续请求）：

| 通道 | 成功 | 平均耗时 |
|---|---|---|
| 每请求新建 CONNECT | 10/12 | 2182 ms |
| 复用一条隧道（当前实现） | 12/12 | 337 ms |

代理地址可用 `.env` 的 `OKX_PROXY` 覆盖（`off` 表示不走代理）；代理失败会自动回退直连，并记住上次成功的通道。

## 均线（EMA）怎么算的、窗口外为什么也有

**结论先说**：均线在**浏览器里按整条序列现算**，拖动 / 缩放 / 改周期都是即时重算，不额外打网络。

为什么不能直接用 Host 发来的数组：**EMA 是递推量** —— 第 i 根的值依赖它前面所有 K 线，
数组前 `period-1` 位必然是 null（EMA480 有 479 个 null，默认窗口才 180 根）。
时间轴往回一拖，可见窗口就滑进了这段 null 里，紫线整段消失 —— 这就是「窗口外的均线没有绘制」。

现在两边分工：

| 角色 | 做什么 |
|---|---|
| Host | 取 **1800 根**（`SERIES_BARS` = 720 可看 + 1080 预热），按整条序列算 EMA20/EMA480，**整条**发给浏览器（`candles` / `ema20` / `ema480` 三者等长对齐） |
| 浏览器 | 拿到序列后按**当前周期**（默认 20/480，可改）在整条序列上算一遍 EMA，画之前再按窗口切片（`emaWindow`） |

所以：窗口停在哪儿，均线就画到哪儿；周期一改，两条线立刻重算重画。

**为什么要留预热段**：序列左端那几根的 EMA 是「刚起步的噪声」—— 第 480 根的 EMA480 其实只是前 480 根的 SMA。
实测（真实 15m 行情）：拿 720 根硬算，最后的可拖范围左端会偏 ~$145（0.17% 现价）；
多留预热后偏差按 `(1-k)^m` 衰减（k = 2/(period+1)），1080 根预热后左端与「用 8000 根算的收敛值」差 ~$40 以内。
预热段只影响最左边一小段，中间和右端与收敛值一致。

- **周期可改**：面板上「均线周期」两个输入框（2–2000，默认 `20` / `480`），改完立刻重算，不用刷新、不用重启宿主。
- **口径一致**：默认周期下浏览器算出的 EMA 与 Host 的 `ema20`/`ema480` 数组**逐点相同**（`client-test` 里做了逐点断言）。
- **不缓存脏值**：`emaFor` 的缓存键含 `(长度, 两个周期, fetchedAt, 首尾时间戳)`，5 秒刷新进来新载荷必重算。

Host 侧取 1800 根 = `/market/candles` 最近 300 根 + `/market/history-candles` 向前翻 15 页 ×100 根。
已收盘的历史 K 线不会再变，单独按 10 分钟缓存，翻页只在冷启动/换周期时发生（实测冷启动 4–7 秒，命中缓存后 15 秒内的请求 2–3 ms）。

## 时间轴：拖动 / 缩放怎么做的

视图用 **`{ size: 窗口根数, rightTs: 右端那根的时间戳 }`** 描述，`rightTs === null` 表示「跟随最新」。

**为什么不用下标记住位置**：每次刷新，数组左边滑走旧 K 线、右边进来新 K 线，下标会整体漂移 ——
用下标记住「用户正在看第 600 根」，15 秒后同一根就变成第 599 根，视图会自己爬。
记住**时间戳**就稳：刷新后二分查回同一根（`indexAfter`），用户看的那几根 K 线停在原地。

- **拖动平移**：`pointerdown` 记下起点与当次视图，`pointermove` 用「总位移 ÷ 每根像素宽」算根数，
  再以**拖动开始时的视图**为基准算新窗口（不是逐帧累加，避免漂移）；`delta > 0` = 往更早看。
- **指针事件而不是鼠标事件**：一套 `pointerdown/move/up` 同时覆盖鼠标、笔与触摸（单指拖动=平移，
  鼠标按住价格轴/时间轴拖动=缩放）；`setPointerCapture` 保证拖到画布外也不丢事件。
- **滚轮缩放是连续的**：倍率取 `exp(deltaY / 420)`（不是「一格 ×1.25」的死档位），触控板与滚轮手感一致；
  `Shift+滚轮` 与触控板的横向滚动（`|deltaX| > |deltaY|`）都当平移。
- **双击复位**：双击价格轴/时间轴区域 → 回最新；双击图区 → 缩放回默认根数（`DEFAULT_WINDOW` = 180）。
- **自动回跟随**：窗口右端顶到最新一根时，`rightTs` 自动变回 `null`；把窗口缩放到超过已有根数时同理。
- **回看提示**：不在最新位置时图表左上角画一个「回看中」角标，右上角出现「回最新 →」按钮。
- **换周期会重置**：不同周期的时间戳完全不同，旧锚点没有意义，所以切周期自动回到「跟随最新」。

### 一个下标口径的坑（最新价线为什么用 `following` 判断）

`drawChart` 拿到的 `candles` 是**窗口切片**，而 `lastIndex` / `lastPrice` 讲的是**整条序列**的最后一根，
两者下标口径不同。判断「该不该画最新价线」用的是 `following`（`rightTs === null`）——
跟随最新时窗口右端必定就是最新那根，这是唯一正确的条件；拿下标去比，回看时就会画错位置。

`viewWindow(candles, view)` 是配套的小工具：把 `rightTs: null` 解析成具体时间戳并返回窗口
（`debug` 里导出、`client-test` 有断言），给"离线算某一帧"的脚本用。

## 悬浮：两档显示（`hitCandle`）

指针进画布就有十字光标，但**数据框只在指针真的压在 K 线的实体或影线上时才弹**：

| 指针位置 | 画什么 |
|---|---|
| 压在实体或上下影线上 | 十字光标竖线落在那一列，横线**吸附到该根收盘价**，右侧轴上标出该收盘价；再叠数据框：时间 / 开 / 高 / 低 / 收 / 量 / 涨跌（+ 两条均线值 + 未收盘标记）。吸附之后指针的真实高度会留一个小圆点，免得看着像"线跑了" |
| 画布空白处（含成交量区） | 只画十字光标（横线跟着鼠标的 y 走）+ 右轴标出「该 y 对应的价格」+ 一行 `鼠标 <价格>` 小标签 |

判定与绘制共用同一套 `xOf / yOf / bodyW`（都在 `hitCandle` 里），所以「看着压上了」和「弹了框」一致。
容差由 `hitTolerance(step)` 给：基础 **3px**（实体只有几像素宽，没有余量几乎点不中），
上限 `step/2` —— 窗口拉到 1800 根时一根只有 0.6px 宽，横向余量收到 1px，
免得"想读这一根却弹了隔壁三根"；纵向不设这个上限（细长影线本来就要宽松）。

> 中途试过一版"价格区内按列命中"（TradingView/ECharts 的默认），
> 好处是不用"扎针"，代价是鼠标在空白处也会弹数据框 —— 实际用起来很吵，所以改回按 K 线命中。

**能往回拖多远**：等于 Host 一次发来的序列长度，即 `SERIES_BARS` 根
（1800 根；15m ≈ 18 天，1D ≈ 1800 天）。客户端请求里的 `limit` 不再影响这件事 ——
载荷永远带整条序列，否则浏览器没法在窗口外算均线。拖到最左边就是序列第 0 根，
那里的 EMA480 从第 480 根起才有值（数学如此，两条线会在最左端自然起步）。

## 时间刻度为什么要对齐整点

旧实现把窗口按根数**等分**取刻度：`index = round((len-1) * i/ticks)`。
结果刻度落在"每 37 分钟一条"这类读不出信息的位置，而且窗口一动刻度就整体跳。

现在 `timeTicks(startTs, endTs, minTicks, maxTicks)`：
先按窗口宽度在候选步长（1s → 5s → … → 1 天 → 30 天）里挑一个"能把窗口切成至少 `maxTicks` 段"的，
再按 2 的整数倍一步算到位（倍率由需要的段数直接推出来），最后从窗口左端取整点往后排，最多 64 条。
刻度因此落在 1m/5m/15m/整小时/整天的边界上，每个刻度的位置同时画一条纵向网格线。

> 这里踩过一个**会把浏览器转死**的坑：第一版判断起点时写的是
> `t = Math.ceil((lo - tzOffset) / step) * step + tzOffset`，在某些时区/浮点组合下
> 算出的 `t > hi`，而 `for (; t <= hi; t += step)` 会**一直加下去**（`t` 越加越大，条件恒假但循环体为空）。
> 现在有硬上限（64 条）+ 明确的升序游标 + `tests/client-test.mjs` 里的看门狗兜底。

## 画线 / 尺子：选中、拖动、删除

每条形如 `{ id, kind, t1, p1, t2, p2, ... }`，存在浏览器 `localStorage`，
按「合约 + 周期」分开（时间轴口径不同，混在一起没意义）。老版本存的画线没有 `id`，
载入时由 `withDrawingIds` 补上（否则没法单独选中）。

| kind | 是什么 | 额外字段 |
|---|---|---|
| `line` | 两点直线（记录两个价位） | — |
| `fib` | 斐波那契回撤（水平比例线） | `levels: [0, 0.5, 1, 1.5, 2]` |
| `measure` | **尺子**：量价格差、涨跌比例、时长、根数 | — |

- **尺子怎么算的**：`measureStats(shape, barMs)` 是纯函数，给 `{ rise, pct, up, bars, ms }`。
  `rise = p2 - p1`、`pct = rise / p1`（`p1 = 0` 时不给比例，避免除零）、
  `bars = |t2 - t1| / barMs + 1`、`ms = |t2 - t1| + barMs`（从起点那根的开盘算到终点那根的收盘）。
  `barMs` 拿不到时 `bars`/`ms` 都是 `null`，标签里就不显示 —— 宁可不显示也不瞎算。
  标签形如 `▲ +1,000.0  +1.26%` / `79,500.0 → 80,500.0  3h15m  13 根`；
  涨绿跌红，但**同时有 ▲/▼ 与正负号**（不能只靠颜色区分）。
- **命中**：`hitDrawing(geom, drawings, x, y)` 依次判两个端点（`DRAW_HIT_PX` = 5px）与线身
  （`pointToSegment` 的垂距；斐波那契判各条水平比例线；尺子判那条斜线）；后画的在上层，先判它。
- **编辑**：无工具时在画线上按下 → 拖端点只动那一头，拖线身则时间与价位一起搬（`moveDrawing` 是纯函数）。
  写回 `drawings` 数组，选中态用 `selectedId` 表示。
- **删除 / 隐藏**：选中后工具条上出现「隐藏 / 删除」，`Delete` 键也能删。
- 画线和 K 线一样吃「按时间戳锚定」的红利：刷新后端点仍钉在同一时刻。

### 端点吸附（`吸附` 开关，默认开）

拖动时端点价格会吸到最近的 OHLC。`snapPriceToOhlc(candles, index, price, yOf, limitPx)`：
把**鼠标所在那根 + 左右各一根**的开/高/低/收都算进来，取屏幕距离最近且不超过 `SNAP_PX`（8px）的那个。

为什么不是只吸当前这根：直接吸"这一根的开/高/低/收"会让四个价位互相抢，手一抖就跳一格；
把邻根也算进来、再按屏幕距离取最近的那个，才既吸得准又不乱跳。
吸附生效时十字光标旁会提示吸到了什么（`高 81,200.0`），右边轴上不用来回对数字。

关掉开关（工具条上的「吸附」）就是鼠标的精确价格 —— 量"差一点点"的时候用得上。



## 私有接口（账户 / 持仓）：已移除

1.3.2 把账户与持仓那整条链路删掉了 —— 路由 `/dsh-btc/account`、签名（`okxSign`）、
私有请求（`okxPrivateApi`）、余额与持仓的字段整理（`normalizeBalance` / `normalizePositions`）
以及 `passphrase` 相关的环境变量全部不再存在。原因是**看板不需要账户信息**，而它是唯一
会发签名私有请求、唯一需要 `passphrase` 的部分；删掉之后这个插件的网络行为收敛成
「只读公开行情」，权限面最小。

如果你之后想重新加回来，需要准备：OKX 私有请求的签名规则
`base64(hmac_sha256(secret, timestamp + METHOD + requestPath + body))`，
以及四个头 KEY / SIGN / TIMESTAMP / PASSPHRASE（`passphrase` 是创建 API key 时你自己设的口令，**不是 secret**）。
`secret` 目前仍在 `currentSettings()` 里读取（仅用于判断「配没配」，从不进任何响应体），可以直接复用。

## 路由（浏览器半只 fetch 同源接口，无 CORS）

| 路由 | 用途 |
|---|---|
| `GET /dsh-btc/board?bar=15m&limit=180[&force=1][&instId=...]` | 看板主数据：价格 + **整条序列**（`candles` / `ema20` / `ema480` 等长）+ 统计 + 元信息。`limit` 现在不影响载荷长度（永远发整条序列，否则浏览器没法在窗口外算均线）。每根 K 线是 `[t, o, h, l, c, v, done]` —— 第 7 位 `done`（1 = 已收盘）用来把「还在动的这一根」画成半透明 + 描边 |
| `GET /dsh-btc/price[?force=1]` | 只要最新价（侧边栏按钮用，轻量） |
| `POST /dsh-btc/env`（body `{"env":"prod"}`） | 切换环境并持久化。**只接受 POST** —— 它是唯一的写操作，而「GET 也能改状态」正是 CSRF 想要的效果，所以把 GET 关掉 |
| `GET /dsh-btc/health` | 自检：环境、密钥指纹、通道、代理、缓存、序列目标 |

选择（环境 + 周期）持久化在 `<workspace>/.dashboard/state.json`（该目录已被 `.gitignore` 忽略）。

> **这四条路由都过了 `connection.requestRejection`**（1.3.2 起）。这条栅栏一次管三件事：
> Host 校验（防 DNS rebinding）、`sec-fetch-site: cross-site` 与 Origin 校验（跨站页面发起的
> 请求一律拒），以及浏览器鉴权（同源请求带的签名 HttpOnly cookie）。判定服务不可用时**返回 503
> 而不是放行** —— 这是安全边界，宁可面板报错也不能静默降级。
>
> 残余风险：默认绑定是回环 `127.0.0.1`，所以局域网访问不到；但**不要用 `--host 0.0.0.0` 把 DSH
> 暴露出去**，栅栏虽然会挡住跨站请求，同网段直连仍是可达面。接口只返回公开行情与密钥掩码，不含 secret。

## 客户端半的测试怎么写的

`tests/client-test.mjs` 不用浏览器：用 profile 里的真 React 把组件渲染成字符串，canvas 用记录型替身。
三处值得知道的细节：

- **看门狗**：这个测试是同步跑完的，正常几秒结束。如果实现里出现条件恒真的循环（真的踩过一次：
  时间刻度起点算错，把客户端转死），进程会占满一个核并且永远不出结果 —— 现在超时（默认 120s，
  可用 `DSH_BTC_TEST_TIMEOUT` 调）会直接报错退出。
- **按绘制阶段分类量落笔数**：断言"两条均线画出来了"时，**不能比 `moveTo` 总数**——
  时间刻度的条数由窗口切在哪个钟点边界决定（可能 3 条也可能 4 条），那是正常的。
  所以测试会给 `drawChart` 的每个绘制阶段插一个标记（重新求值一份带标记的副本），
  把 `moveTo` 归类后再比，比的才是均线本身。
- **真渲染一遍（jsdom）**：`renderToString` 只出字符串、完全不碰事件处理函数，
  所以另有一段用 jsdom + 真 `react-dom/client` 注水渲染，检查 DOM 结构、禁用态与无障碍属性
  （周期标签六个、工具条里的尺子/吸附、没画线时撤销/清空是禁用的、画布可聚焦、没有全局泄漏）。
  找不到 jsdom 就**跳过**（不判失败）。
  > 这一节**不派发事件**，因为 react-dom 在模块加载时就把事件系统绑到了当时的 `window`，
  > 而这里的 jsdom 窗口是后来才装进 globalThis 的 —— 派发过去的 click 能触发原生监听器，
  > 但永远到不了 React 的 `onClick`（三种派发方式实测都一样）。
- **事件处理函数靠静态扫描兜底**：把 `onClick` 里用到的每个名字强制引用一次
  （`var __guard = function(){ return [switchBar, deleteSelected, ...]; }`），
  哪个名字没定义，扫描就会把它报出来。这条是拿真事故换来的 ——
  `switchBar` / `deleteSelected` 被删掉定义之后，`renderToString` 照样全绿，只有真人点一下才炸。

## 踩过的坑（改这块之前先看一眼）

| 症状 | 原因 | 现在的护栏 |
|---|---|---|
| 所有 K 线实体一个颜色（影线颜色是对的） | `bodyOf` 里漏了 `ctx.fillStyle = color`。画布状态是**跨调用共享**的，于是每根实体都用"上一次设过的颜色"填充 | `bodyOf` 自己设 `fillStyle`；测试逐根断言涨绿跌红（实体、影线、量柱三样都断言） |
| 点周期标签 / 按数字键，面板直接消失 | `switchBar` 的定义被删了、只剩一份内联副本挂在 ref 上，而标签的 `onClick` 还在调 `switchBar` → `ReferenceError` → React 卸载整棵树 | 同名函数只有一份（ref 指向函数，不是复制逻辑）；静态扫描「被调用但没有定义的标识符」（强制引用每个事件处理函数用的名字） |
| 点已画的线，面板直接消失 | 同上，`deleteSelected` | 同上 |
| 鼠标在空白处也弹数据框 | 中途试过"价格区内按列命中"，鼠标一进价格区就弹框，实际用起来很吵 | 判定回到 `hitCandle`（压在实体/影线上才算命中），测试里两种位置都断言 |
| 浏览器被转死（占满一个核） | `timeTicks` 的起点在某些时区/浮点组合下落到窗口右端之外，`for (; t <= hi; t += step)` 空转 | 硬上限 64 条 + 明确游标；测试看门狗 |
| 文件里同名函数定义了两遍 | 用脚本按行号替换整块函数时旧块没被完全覆盖；`function` 声明提升后**后一个定义生效**，症状看起来像"改了没生效" | 测试断言 `bodyOf` / `roundBox` 各只定义一次 |
