# dsh-btc-dashboard

DSH 插件：**OKX BTC 合约价格看板**。侧边栏一个按钮，点开是一个全屏面板：

- **最新价格**：OKX `BTC-USDT-SWAP` 的 last / 24h 涨跌 / 买卖价 / 24h 高低 / 24h 量（5 秒级刷新）
- **多周期 K 线**：`1m` `3m` `15m` `1h` `4h` `1D`，点标签切换
- **默认均线**：EMA20 与 EMA480（图例可点击显隐），**周期可在面板上改**，拖动/缩放时在整条序列上动态重算
- **周期切换**：面板顶部标签，选择会被记住（下次打开还是这个周期）
- **时间轴操作**：按住拖动平移、滚轮缩放（以光标为锚点）、双击或点「回最新」回到最新一根
- **悬浮两档**：指针压在 K 线实体/影线上才弹 OHLC / 量 / 均线数据框；只在画布空白处时，十字光标跟着鼠标走，价格轴上标出**鼠标位置对应的价格**
- **画线**：直线 + 斐波那契（默认 0 / 0.5 / 1 / 1.5 / 2，比例可改），按合约+周期分开保存
- **生产 / 模拟环境切换**：面板顶部「模拟 / 生产」分段按钮，选择同样被记住

图表是原生 canvas 画的（蜡烛 + 影线 + 成交量 + 双均线 + 十字光标浮层），不依赖任何图表库。

## 安装状态

已经通过 `plugin_manager` 的 `install_bundle` 装进当前 profile，`package.json` 里是一条链接依赖：

```
@local/dsh-btc-dashboard  link:D:/codes/dsh/btc_dashboard/plugin/dsh-btc-dashboard
```

所以**改这个目录里的代码就是改线上插件**（客户端半由宿主按原样读取文件字节发给浏览器，改完刷新页面即可；Host 半是已加载的 ESM 模块，代码改动需要重启宿主才生效）。

- 卸载：`plugin_manager` → `remove_bundle`，target `@local/dsh-btc-dashboard`
- 临时停用：`set_bundle` / `set_plugin`，enabled=false

## 两个环境的语义（重要，别被「密钥」误导）

| | 生产（prod） | 模拟（demo） |
|---|---|---|
| 读取的密钥 | `PROD_OKX_API_KEY/SECRET` | `DEBUG_OKX_API_KEY/SECRET` |
| 请求头 | 无 | `x-simulated-trading: 1` |
| 行情价格 | 实盘 | 与实盘一致（同一市场数据） |

**看板只用 OKX 公开行情接口（`/market/ticker`、`/market/candles`、`/market/history-candles`），不需要签名**，所以：

1. 密钥不是取价的前提 —— 面板照常工作，即使 `.env` 里一把钥匙都没有（页脚会提示）；
2. 密钥唯一的作用是「确认这一环境配了哪把钥匙」，面板只展示**掩码指纹**（如 `abcd12…9xyz`），secret 只用来判断「配没配」，永远不进浏览器；
3. **本插件不发任何私有请求**（不读账户余额、不读持仓），因此不需要 `passphrase`，也不需要签名 —— 相关代码已在 1.3.2 移除。

## 这台机器上的一个坑：必须走本地代理

本机 DNS 把 `www.okx.com` 解析成 `169.254.0.2`（链路本地黑洞地址），直连必然超时。
所以插件默认走本地代理 `http://127.0.0.1:7897`：先 `CONNECT` 建隧道，再在隧道里握 TLS，**并复用同一条 keep-alive 隧道**。

实测对比（12 次连续请求）：

| 通道 | 成功 | 平均耗时 |
|---|---|---|
| 每请求新建 CONNECT | 10/12 | 2182 ms |
| 复用一条隧道（当前实现） | 12/12 | 337 ms |

代理地址可用 `.env` 的 `OKX_PROXY` 覆盖（`off` 表示不走代理）；代理失败会自动回退直连，并记住上次成功的通道。

## 均线（EMA）怎么算的、窗口外为什么也有

**结论先说**：均线在**浏览器里按整条序列现算**，拖动 / 缩放 / 改周期都是即时重算，不额外打网络。

为什么不能直接用 Host 发来的数组：**EMA 是递推量** —— 第 i 根的值依赖它前面所有 K 线，
数组前 `period-1` 位必然是 null（EMA480 有 479 个 null，默认窗口才 180 根）。
时间轴往回一拖，可见窗口就滑进了这段 null 里，紫线整段消失 —— 这就是「窗口外的均线没有绘制」。

现在两边分工：

| 角色 | 做什么 |
|---|---|
| Host | 取 **1800 根**（`SERIES_BARS` = 720 可看 + 1080 预热），按整条序列算 EMA20/EMA480，**整条**发给浏览器（`candles` / `ema20` / `ema480` 三者等长对齐） |
| 浏览器 | 拿到序列后按**当前周期**（默认 20/480，可改）在整条序列上算一遍 EMA，画之前再按窗口切片（`emaWindow`） |

所以：窗口停在哪儿，均线就画到哪儿；周期一改，两条线立刻重算重画。

**为什么要留预热段**：序列左端那几根的 EMA 是「刚起步的噪声」—— 第 480 根的 EMA480 其实只是前 480 根的 SMA。
实测（真实 15m 行情）：拿 720 根硬算，最后的可拖范围左端会偏 ~$145（0.17% 现价）；
多留预热后偏差按 `(1-k)^m` 衰减（k = 2/(period+1)），1080 根预热后左端与「用 8000 根算的收敛值」差 ~$40 以内。
预热段只影响最左边一小段，中间和右端与收敛值一致。

- **周期可改**：面板上「均线周期」两个输入框（2–2000，默认 `20` / `480`），改完立刻重算，不用刷新、不用重启宿主。
- **口径一致**：默认周期下浏览器算出的 EMA 与 Host 的 `ema20`/`ema480` 数组**逐点相同**（`client-test` 里做了逐点断言）。
- **不缓存脏值**：`emaFor` 的缓存键含 `(长度, 两个周期, fetchedAt, 首尾时间戳)`，5 秒刷新进来新载荷必重算。

Host 侧取 1800 根 = `/market/candles` 最近 300 根 + `/market/history-candles` 向前翻 15 页 ×100 根。
已收盘的历史 K 线不会再变，单独按 10 分钟缓存，翻页只在冷启动/换周期时发生（实测冷启动 4–7 秒，命中缓存后 15 秒内的请求 2–3 ms）。

## 时间轴：拖动 / 缩放怎么做的

视图用 **`{ size: 窗口根数, rightTs: 右端那根的时间戳 }`** 描述，`rightTs === null` 表示「跟随最新」。

**为什么不用下标记住位置**：每次刷新，数组左边滑走旧 K 线、右边进来新 K 线，下标会整体漂移 ——
用下标记住「用户正在看第 600 根」，15 秒后同一根就变成第 599 根，视图会自己爬。
记住**时间戳**就稳：刷新后二分查回同一根（`indexAfter`），用户看的那几根 K 线停在原地。

- **拖动平移**：`mousedown` 记下起点与当次视图，`mousemove` 用「总位移 ÷ 每根像素宽」算根数，
  再以**拖动开始时的视图**为基准算新窗口（不是逐帧累加，避免漂移）；`delta > 0` = 往更早看。
- **滚轮缩放**：React 的 `onWheel` 是被动的，`preventDefault()` 无效，所以原生挂一个 `{ passive: false }` 监听；
  以光标所在的相对位置为锚点缩放（`zoomView(..., anchorFraction)`），中点在缩放前后基本不动。
- **自动回跟随**：窗口右端顶到最新一根时，`rightTs` 自动变回 `null`；把窗口缩放到超过已有根数时同理。
- **回看提示**：不在最新位置时图表左上角画一个「回看中」角标，右上角出现「回最新 →」按钮。
- **换周期会重置**：不同周期的时间戳完全不同，旧锚点没有意义，所以切周期自动回到「跟随最新」。

## 悬浮：两档显示（`hitCandle`）

指针进画布就有十字光标，但**数据框只在真的压在某根 K 线上时才弹**：

| 指针位置 | 画什么 |
|---|---|
| 画布空白处 | 十字光标（横线跟着鼠标的 y 走）+ 右轴标出「该 y 对应的价格」+ 一行 `鼠标 <价格>` 小标签 |
| K 线实体或上下影线上 | 再叠一个数据框：时间 / 开 / 高 / 低 / 收 / 量 / 涨跌（+ 两条均线值），横线吸附到该根收盘价 |

命中判定 [`hitCandle`](client.js) 用的就是绘制时同一套 `xOf / yOf` 和同一个实体宽度 `bodyW`，
所以「看着压上了」和「弹了框」一致；另有 `CANDLE_HIT_PX`（默认 3px）容差，免得几像素宽的实体点不中。
指针在成交量区、或者落在窗口最左/最右那一列之外时，按「没命中 K 线」处理，只显示鼠标价格。

**能往回拖多远**：等于 Host 一次发来的序列长度，即 `SERIES_BARS` 根
（1800 根；15m ≈ 18 天，1D ≈ 1800 天）。客户端请求里的 `limit` 不再影响这件事 ——
载荷永远带整条序列，否则浏览器没法在窗口外算均线。拖到最左边就是序列第 0 根，
那里的 EMA480 从第 480 根起才有值（数学如此，两条线会在最左端自然起步）。



## 私有接口（账户 / 持仓）：已移除

1.3.2 把账户与持仓那整条链路删掉了 —— 路由 `/dsh-btc/account`、签名（`okxSign`）、
私有请求（`okxPrivateApi`）、余额与持仓的字段整理（`normalizeBalance` / `normalizePositions`）
以及 `passphrase` 相关的环境变量全部不再存在。原因是**看板不需要账户信息**，而它是唯一
会发签名私有请求、唯一需要 `passphrase` 的部分；删掉之后这个插件的网络行为收敛成
「只读公开行情」，权限面最小。

如果你之后想重新加回来，需要准备：OKX 私有请求的签名规则
`base64(hmac_sha256(secret, timestamp + METHOD + requestPath + body))`，
以及四个头 KEY / SIGN / TIMESTAMP / PASSPHRASE（`passphrase` 是创建 API key 时你自己设的口令，**不是 secret**）。
`secret` 目前仍在 `currentSettings()` 里读取（仅用于判断「配没配」，从不进任何响应体），可以直接复用。

## 路由（浏览器半只 fetch 同源接口，无 CORS）

| 路由 | 用途 |
|---|---|
| `GET /dsh-btc/board?bar=15m&limit=180[&force=1][&instId=...]` | 看板主数据：价格 + **整条序列**（`candles` / `ema20` / `ema480` 等长）+ 统计 + 元信息。`limit` 现在不影响载荷长度（永远发整条序列，否则浏览器没法在窗口外算均线） |
| `GET /dsh-btc/price[?force=1]` | 只要最新价（侧边栏按钮用，轻量） |
| `POST /dsh-btc/env`（body `{"env":"prod"}`） | 切换环境并持久化。**只接受 POST** —— 它是唯一的写操作，而「GET 也能改状态」正是 CSRF 想要的效果，所以把 GET 关掉 |
| `GET /dsh-btc/health` | 自检：环境、密钥指纹、通道、代理、缓存、序列目标 |

选择（环境 + 周期）持久化在 `<workspace>/.dashboard/state.json`（该目录已被 `.gitignore` 忽略）。

> **这四条路由都过了 `connection.requestRejection`**（1.3.2 起）。这条栅栏一次管三件事：
> Host 校验（防 DNS rebinding）、`sec-fetch-site: cross-site` 与 Origin 校验（跨站页面发起的
> 请求一律拒），以及浏览器鉴权（同源请求带的签名 HttpOnly cookie）。判定服务不可用时**返回 503
> 而不是放行** —— 这是安全边界，宁可面板报错也不能静默降级。
>
> 残余风险：默认绑定是回环 `127.0.0.1`，所以局域网访问不到；但**不要用 `--host 0.0.0.0` 把 DSH
> 暴露出去**，栅栏虽然会挡住跨站请求，同网段直连仍是可达面。接口只返回公开行情与密钥掩码，不含 secret。

## 可调参数（都在 `index.js` 顶部）

| 常量 | 默认 | 说明 |
|---|---|---|
| `DEFAULT_ENV` | `demo` | 首次运行（没有 state.json 时）的环境 |
| `HOT_TTL` | 15000 ms | 最近一段 K 线的热缓存时长；调小 → K 线更快跟随，代价是请求更频繁 |
| `HISTORY_TTL` | 600000 ms | 已收盘历史 K 线的缓存时长 |
| `SERIES_BARS` | 1800 | 取多少根 = **时间轴能往回拖多远**，同时决定均线预热有多深（720 可看 + 1080 预热） |
| `MAX_PAGES` | 20 | 向前翻页上限（1800 根 ≈ 300 + 15×100，冷启动实测 4–7 秒） |
| `MAX_DISPLAY` | 720 | 只用来算「默认展示窗口」的统计口径（载荷发整条序列） |
| `EMA_FAST` / `EMA_SLOW` | 20 / 480 | 均线默认周期（浏览器侧可在面板上改） |
| `REQUEST_TIMEOUT` | 12000 ms | 单次 OKX 请求超时（每个通道最多试 2 次） |

客户端侧的常量在 `client.js` 顶部：`REFRESH_MS`（轮询间隔 5000）、`FETCH_LIMIT`（一次请求多少根 720）、
`RANGES`（窗口快捷档位 60/120/180/300）、`MIN_WINDOW`（缩放下限 30 根）、
`DEFAULT_EMA_FAST` / `DEFAULT_EMA_SLOW`（20 / 480）、`EMA_PERIOD_MIN` / `EMA_PERIOD_MAX`（2 / 2000）。

工作区（`.env` 与 `.dashboard/` 的所在目录）按这个顺序解析：环境变量 `DSH_BTC_WORKSPACE` →
插件位置往上两级（能同时看到 `.env` 或 `plugin/` 时认定）→ 当前工作目录。所以仓库 clone 到任何
路径都能直接跑，不依赖本机绝对路径。

测试脚本同样不再硬编码路径：共用的 `tests/_paths.mjs` 按脚本自身位置推导工作区，
profile 位置读 `DSH_PROFILE_DIR`（或 `DSH_HOME` / `DSH_PROFILE`），
自带插件的对照文件可用 `DSH_BRAND_CLIENT` 指定 —— 找不到时那部分对照会**跳过**而不是误判失败。
